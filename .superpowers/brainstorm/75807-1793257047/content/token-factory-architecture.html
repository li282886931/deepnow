Token 工厂：推荐架构

当前 DeepNow 作为网关与管理控制台，Token 治理能力先以内聚模块落地，再通过适配器扩展 Vault、KMS、消息队列和外部审批。

推荐方案：模块化单体 + 事件驱动治理

首期落地边界

A

模块化单体（推荐）

复用当前 Go 网关、SQLite 和 uni-app x 控制台，先交付可运行 MVP；Vault/KMS、消息队列通过接口隔离。

B

立即拆微服务

直接拆 Issuer、Policy、Approval、Risk 等服务，边界清晰，但当前项目会承担较大的部署和联调成本。

C

独立 Token 服务

Token 工厂与 DeepNow 完全独立，通过 Gateway Adapter 接入；适合长期平台化，但首期交付链路最长。
